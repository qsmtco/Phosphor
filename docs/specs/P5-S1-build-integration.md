## 1. Scope

Make the GrapheneOS `akita` build produce **five empty-but-real Phosphor modules** — four of them Phosphor *processes* in the architecture §2.1 sense (`phosphor-ctl` is a read-only on-demand tool in the existing `shell` domain, see §2) — plus the build plumbing that every later spec fills in:

| Module (soong name) | Kind | Install location | Behaviour at S1 |
|---|---|---|---|
| `phosphor-agentd` | `cc_binary` | `/system/bin/phosphor-agentd` | stub `main()` → exit 0. Never started (no `.rc` until S4). |
| `phosphor-keygate` | `cc_binary` | `/system/bin/phosphor-keygate` | stub `main()` → exit 0. Never started (no `.rc` until S3). |
| `phosphor-ctl` | `cc_binary` | `/system/bin/phosphor-ctl` | stub `main()` → prints `phosphor-ctl: not implemented` to stderr, exit 2. (Filled in by S8; **not** a fifth Phosphor process/domain — it is an on-demand tool invoked from `adb shell` and runs in the existing `shell` domain, so it needs no `phosphor_*` domain and no fifth AID. Fixed by S2 A8; see §2 last row.) |
| `PhosphorShell` | `android_app` | `/system/priv-app/PhosphorShell/PhosphorShell.apk` | valid APK, package `com.phosphor.shell`, **zero declared components**. (Filled in by S5.) |
| `PhosphorBroker` | `android_app` | `/system/priv-app/PhosphorBroker/PhosphorBroker.apk` | valid APK, package `com.phosphor.broker`, **zero declared components**, zero permissions. (Filled in by S6.) |

Plus: one product fragment, one sepolicy directory wired but empty, one read-only policy artifact staged, and one local-manifest entry.

**"Empty" is a hard requirement, not a placeholder word.** An empty module must (a) compile, (b) install to the path above, (c) appear in `product_packages.txt`, and (d) **cause no observable device behaviour change whatsoever** — no process starts, no service registers, no property is written, no file under `/data` is created. S1's acceptance is therefore build-only and static; the first boot check of any Phosphor component belongs to S3/S4 and requires PM approval for that device operation.

### Non-goals (explicitly not in S1)

- No sepolicy content (S2), no init `.rc` files (S3, S4), no behaviour in any binary or app.
- No new `lunch` target. **The build recipe must not change** (see §5 A2).
- No device operation of any kind: no flash, no wipe, no reboot, no `adb` write.
- No modification of `vendor/google_devices/akita` (generated by adevtool — regenerated, never hand-edited; `docs/PROJECT-STATUS.md` §6).
- No `OFFICIAL_BUILD=true` (`docs/PROJECT-STATUS.md` §9 — it points the Updater at GrapheneOS's real server).

## 3. Behaviour contract

**B1 — One new repository, one mount point.** Phosphor's Phase 5 payload lives in a single new repository mounted at `packages/phosphor/` in the GrapheneOS tree. It is *added by local manifest*, so **no GrapheneOS-owned project is forked and no GrapheneOS file is edited** except the single product-inheritance line in B4.

**B2 — Directory layout (canonical for all later specs).**

```
packages/phosphor/
  phosphor.mk                     # product fragment: PRODUCT_PACKAGES, PRODUCT_COPY_FILES, SYSTEM_EXT_*_SEPOLICY_DIRS
  sepolicy/                       # wired empty in S1; content owned by S2
    public/                       # -> SYSTEM_EXT_PUBLIC_SEPOLICY_DIRS
    private/                      # -> SYSTEM_EXT_PRIVATE_SEPOLICY_DIRS
  risk-policy/risk-policy.json    # read-only policy artifact (typed by S2, consumed by S6/S7)
  init/                           # empty in S1; phosphor_keygate.rc (S3), phosphor_agentd.rc (S4)
  services/PhosphorAgentd/        # cc_binary phosphor-agentd   (S4)
  services/PhosphorKeygate/       # cc_binary phosphor-keygate  (S3)
  services/PhosphorDiagnostics/   # cc_binary phosphor-ctl      (S8)
  services/PhosphorIpc/           # AIDL + wire headers shared by S4/S6/S7
  apps/PhosphorShell/             # android_app PhosphorShell   (S5)
  apps/PhosphorBroker/            # android_app PhosphorBroker  (S6)
```

**B3 — Module definitions.** `cc_binary` modules use `stem:` equal to the module name so the installed filename is `phosphor-agentd` etc.; `android_app` modules use `platform_apis: true`, `certificate: "platform"`, `privileged: true`, and a minimal valid `AndroidManifest.xml` (package only, no `<application>` components beyond `android:label`). No module declares `init_rc` in S1 — the `.rc` install is part of S3/S4 so that S1 cannot start anything at boot. With `privileged: true`, Soong installs both apps under `/system/priv-app/` (`build/soong/java/app.go:1091-1093` — `else if a.Privileged()`, no override); every install path in this spec set uses `priv-app` (rev-2 erratum, verified in-tree 2026-11-10).

**B4 — Product hook, exactly one line in a third-party file.** `packages/phosphor/phosphor.mk` is inherited by appending exactly one line to `vendor/adevtool/config/mk/google_devices/device/akita/device.mk`:

```make
$(call inherit-product, packages/phosphor/phosphor.mk)
```

This is the only writable seam: the generated `vendor/google_devices/akita/akita.mk` inherits that file (`docs/PHASE-2-SOURCE-AND-BUILD-FOUNDATION.md` §4), and product inheritance is not otherwise expressible from outside the product's own makefile chain. The consequence is **mandatory**: `PATH="$HOME/android-sdk/node24/bin:$PATH" vendor/adevtool/bin/run generate-all -d akita` must be re-run so `vendor/google_devices/akita` is regenerated from its source config rather than hand-edited. (Trap: adevtool aborts on the nsjail stderr line — re-apply `scripts/host-fix-nsjail-userns.sh` first; it uses the `vendor/adevtool/dl/` cache, so no network is required.)

**B5 — `phosphor.mk` content.**

```make
PRODUCT_PACKAGES += \
    phosphor-agentd \
    phosphor-keygate \
    phosphor-ctl \
    PhosphorShell \
    PhosphorBroker

PRODUCT_COPY_FILES += \
    packages/phosphor/risk-policy/risk-policy.json:$(TARGET_COPY_OUT_SYSTEM)/etc/phosphor/risk-policy.json

SYSTEM_EXT_PUBLIC_SEPOLICY_DIRS += packages/phosphor/sepolicy/public
SYSTEM_EXT_PRIVATE_SEPOLICY_DIRS += packages/phosphor/sepolicy/private
```

**The two variable names above are not negotiable in this tree.** `BOARD_PLAT_PUBLIC_SEPOLICY_DIR` / `BOARD_PLAT_PRIVATE_SEPOLICY_DIR` are `KATI_obsolete_var` in this tree and therefore **hard-abort the build**, not warn:

- `build/make/core/config.mk:163` — `BOARD_PLAT_PUBLIC_SEPOLICY_DIR` → "Use SYSTEM_EXT_PUBLIC_SEPOLICY_DIRS instead"
- `build/make/core/config.mk:164` — `BOARD_PLAT_PRIVATE_SEPOLICY_DIR` → "Use SYSTEM_EXT_PRIVATE_SEPOLICY_DIRS instead"
- `system/sepolicy/README.md:48-49` — "The old `BOARD_PLAT_PUBLIC_SEPOLICY_DIR` … have been deprecated in favour of `SYSTEM_EXT_*`."

The abort fires on the first `m`, i.e. **before any Phosphor module is reached**, and it aborts the whole build that gates S2–S8. `SYSTEM_EXT_*` is wired live: `build/make/core/soong_config.mk:219-220` feeds them to Soong as `SystemExtPublicSepolicyDirs`/`SystemExtPrivateSepolicyDirs`, consumed at `system/sepolicy/build/soong/build_files.go:88-89`. `system_ext` policy dirs are also admitted to the `sepolicy_neverallows` target (`system/sepolicy/Android.bp:943`), which is what makes S2's `neverallow` set legal there (S2 C14).

Both sepolicy directories ship with a `README` only in S1 (an empty directory in these variables is legal and produces no policy). `[VERIFY AT BUILD: `rg -n 'BOARD_PLAT_(PUBLIC|PRIVATE)_SEPOLICY_DIR|SYSTEM_EXT_(PUBLIC|PRIVATE)_SEPOLICY_DIRS' build/make/core` — the obsolete names must appear **only** on the `KATI_obsolete_var` lines at `config.mk:163-164`; if any `SYSTEM_EXT_*` spelling differs in this tree, record the actual name in the S1 completion note before writing `phosphor.mk`, and never fall back to a `BOARD_PLAT_*` name — it aborts the build.]`

**B6 — Local manifest.** `.repo/local_manifests/phosphor.xml`:

```xml
<manifest>
  <remote  name="phosphor" fetch="ssh://git@github.com/qsmtco" />
  <project name="Phosphor-platform" path="packages/phosphor" remote="phosphor" revision="refs/heads/main" />
</manifest>
```

Development variant (until the remote exists): replace `remote` with `fetch="file:///home/cptjaqx/projects/Phosphor-platform.git"` against a local bare mirror. Afterwards `repo manifest -r > .repo/manifest-pinned.xml` must be re-run so the pin file records our project at a commit hash. The Phase 2 provenance claim (`docs/PHASE-2-SOURCE-AND-BUILD-FOUNDATION.md` §3.4) remains valid for GrapheneOS projects; our project is provenance-recorded separately and this split must be stated in the completion note.

**B7 — Stub sources.** `services/*/main.cpp` is exactly:

```cpp
int main() { return 0; }         // phosphor-ctl prints one line to stderr and returns 2
```

App stubs contain a single `AndroidManifest.xml` with `<manifest package="com.phosphor.shell">` (resp. `.broker`) and nothing else, and no `src/` beyond an empty package directory.

**A5 — Third-party modification surface is exactly one line.** `repo status -j24` (or `git status` per project) shows modifications **only** in `vendor/adevtool` (one line added to `device.mk`) and in `packages/phosphor` (new). Any other modified GrapheneOS project fails this spec. The `repo status` output is attached as evidence.

**A6 — Provenance recorded.** Completion note states: (a) our project's commit, (b) the re-pinned `manifest-pinned.xml` line count delta, (c) that GrapheneOS's own signed-tag verification is unaffected, (d) the adevtool regeneration was performed from config, not by hand-editing `vendor/google_devices`.

**A7 — No device operation performed.** `git diff` of `docs/` and the absence of any `adb`/`fastboot` invocation in the session log. S1 is a build-only spec; the first boot of Phosphor code is gated behind S3/S4 + PM approval.

## 6. Edge cases and failure modes

| Case | Required handling |
|---|---|
| `adevtool generate-all` aborts on the nsjail stderr line | Re-apply `scripts/host-fix-nsjail-userns.sh`; do **not** judge the fix with a bare `nsjail` probe (it fails even when correct — PROJECT-STATUS §9). |
| `vendor/google_devices/akita` shows the line as hand-edited | Stop; regenerate. A hand-edit is silently lost on the next `generate-all`. |
| Module name collision with a GrapheneOS module | Pre-flight `rg -n '"phosphor-|"Phosphor' --glob Android.bp` across the tree before adding; a duplicate soong module name is a hard build error, and GrapheneOS names its apps by module (`PROJECT-STATUS` §9). |
| `soong_namespace` in a parent directory hides `packages/phosphor` modules | Verify no `soong_namespace {}` in `packages/` chain; if present, add a matching `soong_namespace` + `import` and record it. |
| Disk pressure | `out/` is ~107 GB and the delta must be recorded before the build, not after a failure. |
| Build "succeeds" but a module is missing from `product_packages.txt` | This is the exact trap MAJOR-4/§3 warns about in another form: the artifact, not the message, is the evidence. A4/A3 counts are the gate. |
| `lunch akita-user` or `akita-ap2a-user` accepted-looking | Rejected by project rule; only `akita-cur-user` continues (`PROJECT-STATUS` §6). |
| Fingerprint | Expected to end `:user/test-keys` at this stage — correct, not a defect. |
