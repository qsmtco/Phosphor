438|## 9. Decisions and open questions for the Captain (real architectural forks)
439|
440|*Phase-5-gating:* **OQ-1, OQ-2, OQ-3, OQ-4 — all four DECIDED by the Captain on 2026-11-10** (audit MINOR-8 — OQ-5/6/7 do not gate Phase 5 and remain open by design, listed for completeness). The rulings are recorded verbatim in intent below; the recommendations that preceded them are retained so the trail shows what was advised and what was ruled.
441|
442|1. **OQ-1 — Vanadium's signature (gates §1.1, §4). DECIDED.** ~~Options: (a) ride GrapheneOS-signed Vanadium … (b) build Chromium from source under our keys …~~ **RULING: ride GrapheneOS-signed Vanadium for Phases 4–9, revisit before Phase 12.** Accepted consequence, recorded: the rendering engine stays under GrapheneOS's trust anchor and our trust requirement sits on the shell app; this is a deliberate acceptance, not an oversight (SPEC-001 §14.2, §1.1). The revisit at Phase 12 is bound to relock (OQ-5), because that is the point at which verification of the engine's provenance under our own key would become meaningful.
443|2. **OQ-2 — Agent-service credential trust anchor (gates §5, §6.4). DECIDED.** ~~Keystore-wrapped vs plain `/data` config …~~ **RULING: Keystore-wrapped (hardware-backed, StrongBox-capable on the 8a) + per-flash credential provisioning.** Accepted consequence, recorded explicitly: because the bootloader is unlocked until relock (OQ-5, Phase 12), **on-device secret-at-rest is *best-effort*, not a guarantee** — an attacker with the unlocked device can reach what the Keystore wraps. Per-flash provisioning means a re-flash requires re-provisioning, which is a deliberate cost, not a bug. §6.4 carries this qualifier on the credential-store row.
444|3. **OQ-3 — Approval-card host process (gates Phase 5 UI/manifest work). DECIDED.** ~~Broker-hosted vs shell-hosted …~~ **RULING: broker-hosted.** Rationale as ruled: highest assurance — the card renders from the broker's registry even with the shell dead, broken, or showing attacker-influenced content. Accepted consequence: the broker must be able to show UI, which constrains OQ-4 and is one of the reasons OQ-4 is a standalone app rather than a `system_server` injection. §6.2 and §8's map now draw this as decided.
445|4. **OQ-4 — Broker hosting shape (gates Phase 5 manifest/sepolicy). DECIDED.** ~~Standalone platform-signed app vs `system_server` injection vs hybrid …~~ **RULING: standalone platform-signed app; escalate (to `system_server` injection or a hybrid) only if a specific capability demands it** — and that escalation is a recorded, per-capability decision, not a drift. Note MINOR-6's constraint in support: `wifi.toggle` requires the broker to be a system app, which this ruling satisfies.
446|5. **OQ-5 — Relock timing (Phase 12 gate, not Phase 5). Open.** The design works better relocked (verified boot under our key, meaningful StrongBox anchoring) but relock wipes and bricks-on-bad-build. Recommend Phase 12. Note the coupling to the OQ-1 revisit and to OQ-2's best-effort qualifier: relock is what turns both from accepted risk into a guarantee.
447|6. **OQ-6 — STT engine (decide Phase 7). Open.** whisper.cpp (proven, fully local, models on-device) vs `SpeechRecognizer` on-device recognizer (platform-integrated, less control). Both behind one interface; model packaging is a build-design decision.
448|7. **OQ-7 — GMS compatibility retention (decide Phase 9). Open.** Nothing in this architecture depends on it either way; recommend drop-by-default.
449|8. **OQ-8 — Residual SPEC-002 L1 (§6.6). Open.** Recommend declaring L1 satisfied-by-platform; needs sign-off because it retires a SPEC-002 level.

469|```
470|Z0 untrusted ── web/search content, remote model output, notification text, broker results, logcat
471|      │                                     │
472|      │ (R-QUAR envelope / REC-5)           │ (R-QUAR envelope)
473|      ▼                                     ▼
474|Z2 agentd (unprivileged brain) ◀─────────────── broker results
475|      │  classify (R-GATE-1/4)  ── DESTRUCTIVE/DESTRUCTIVE-READ ──▶ Z3 broker → approval card (Z5 user)
476|      │  normalise HTML (§4.1 L1)
477|      ▼ AF_UNIX socket (SO_PEERCRED)
478|Z1 shell → WebView renders agent HTML (inline JS allowed, remote subresources blocked both layers)
479|      │  page JS ──phosphorApi only──▶ shell ──binder──▶ Z3 broker ──▶ Z4 Android services
480|      ▲                                                      │
481|      └──────────── user taps / voice (Z5 human) ◀────────────┘
482|```
483|
484|**B. Trust zones**
485|
486|| Zone | Components | What it may do | What it must never do |
487||---|---|---|---|
488|| **Z0 untrusted input** | web content, search results, model output, remote notification bodies, diagnostic strings | enter context only inside R-QUAR envelopes | be treated as instruction |
489|| **Z1 renderer** | WebView + agent-generated page JS | render, run inline JS, call `phosphorApi` | hold credentials; fetch remote subresources; render an approval card |
490|| **Z2 brain** | `phosphor_agentd` | compute, network egress, classify, call broker, call shell over the socket | hold Android capabilities; read secret paths; write policy artifact |
491|| **Z3 privileged** | `PhosphorBroker` | hold the §3 permissions, execute approved calls, own the approval registry | exceed the §3 API surface; write policy artifact; classify more weakly than agentd |
492|| **Z4 platform** | `system_server`, SELinux, init | arbitrate hardware, enforce policy, gate safe boot | be bypassed by a Phosphor domain (neverallow-enforced) |
493|| **Z5 out-of-band / human** | host+cable (fastboot, safe-boot property), the user's taps and key chord | approve/deny, flash, force safe boot | be reachable from any in-device Phosphor process |

512|**Exit-criterion assessment.** The major boundaries, implementation locations and trust assignments are specified well enough to begin Phase 5 without guessing, and **the four dependencies that previously made closure conditional are no longer open**: OQ-1 (engine trust — decided: ride GrapheneOS-signed Vanadium, Phases 4–9), OQ-2 (credential anchor — decided: Keystore-wrapped + per-flash, best-effort at rest until relock), OQ-3 (card host — decided: broker-hosted), OQ-4 (broker hosting — decided: standalone platform-signed app, escalate only on a capability's demand) were all ruled by the Captain on 2026-11-10 (§9). **Phase 4 is therefore CLOSED — on the declared-debt boundary stated in §10.2.** That phrase is deliberate and is the whole of the claim: closure means every architectural fork is decided and every unverified assertion is *named with an owner and a phase* above; it does not mean the residual debt is discharged. The two rows that were genuinely unverified claims have been closed by in-tree evidence in this revision (the three protection levels; app-layer property visibility), so no item in §10.2 is an unexamined assertion any longer. Closable without this patch would have required reopening the architecture; closable *only* on this boundary is the honest statement.
