248|## 6. Edge cases and failure modes
249|
250|| Case | Required handling |
251||---|---|
252|| `neverallow` in a device dir | Must compile-fail. Confirm C14 first; if the tree rejects it, the fix is the dir choice, **never** deleting the rule. |
253|| `mmap_exec_file_perms` reintroduced by a helpful editor | Build fails. Cite NEW-7/C11 and restore `:file *`. |
254|| `neverallow phosphor_keygate { system_prop -phosphor_safeboot_prop }:property_service set` — subtraction syntax | C10 shows the in-tree shape; if the build rejects the exact string, use the enumerated alternative and record it. Do not fall back to the blanket form (§8 explicitly forbids it). |
255|| `exact bool` on a `persist.*` property | `persist.*` is `string`; use `exact string` for the latch (see §3.1) and keep `exact bool` only for the `sys.*` decision. Mixing them fails at init property-load time, not at build time — a silent-late failure. |
256|| Latch value semantics | `persist.*` must be non-empty; init rejects empty values for `persist.`. `setprop persist.phosphor.safeboot 1` is the only meaningful write. |
257|| Type exists but no context | Property falls back to `default_prop` (C6) and *silently* loses the grant. A4/A5's `rg` on the **compiled** contexts files is the check, not on the source. |
258|| `app_domain()` needs a matching `seapp_contexts` entry | Both halves or the app runs as `untrusted_app` and none of the grants apply — silently. A3's liveness proof covers it. |
259|| Four AIDs collide with an existing OEM AID | `[VERIFY]` at C15; a collision is an SELinux *and* a filesystem-ownership fault. |
260|| `get_prop(appdomain, …)` looks like over-grant | It is intended (§3.3) and mirrors `app.te:40`. Do not narrow it to our two packages without recording why — the safe-boot flag must be readable by anything that must decide whether to be the surface. |
