404|**Reconciliation notes (audit MAJOR-9 — map now agrees with §2.1/§5/§6.2):**
405|1. The approval dialog is **inside the broker's box**: OQ-3 was DECIDED (Captain, 2026-11-10) as broker-hosted, so the map draws the decided placement rather than a shared annotation. §6.2 states the ruling and the accepted consequence (the broker must be able to show UI, which is part of why OQ-4 is a standalone platform-signed app).
406|2. The shell's permission line says **`RECORD_AUDIO` only**, matching §5 step 1, instead of claiming it holds no capability permissions.
407|3. `phosphor_agentd` has **no binder permission to the shell**. Shell↔agentd is a `AF_UNIX` `SOCK_SEQPACKET` channel that the *shell* connects to, with agentd verifying `SO_PEERCRED` and the group/label. This removes rev 1's contradictory "neverallow … except to broker + shell".
408|4. The shell↔agentd mechanism is **chosen, not left as "binder AIDL / local socket"**: a Unix socketpair, because a Rust daemon would otherwise have to implement the binder wire protocol or be fronted by a Java service, and because it gives length-framed messages with credential checks. Its trust properties are stated: the channel carries the turn and the render payload, is **outside** the broker's classifier, and is the reason §4.1 exists.
409|
410|**SELinux requirements (Phase 5 deliverables).** Written to be compile-ready, because a rule that cannot be expressed invites a Phase 5 author to drop it and silently lose the guarantee:
411|
412|- `neverallow phosphor_agentd` any capability-adjacent device node (telephony, camera, location, netlink for radios).
413|- `neverallow phosphor_agentd { phosphor_broker }:binder call` — the *only* permitted binder target; nothing to the shell.
414|- `neverallow phosphor_shell` binder to capability services directly (broker or nothing).
415|- **The policy artifact gets a type.** It is a **JSON document** (`risk-policy.json`), stored as type **`phosphor_risk_policy_file`**; `neverallow { phosphor_agentd phosphor_broker phosphor_shell phosphor_keygate } phosphor_risk_policy_file:file { write append create rename setattr unlink };` — read is deliberately allowed for agentd and broker (§6.3) and absent for shell, so this rule states the write ban against its named type rather than a vague "any Phosphor domain".
416|- **`phosphor_keygate`'s file access, stated as the permission checks it actually is** (NEW-3 — "touching the agent's binary" is not a SELinux predicate, so it is enumerated): `neverallow phosphor_keygate phosphor_agentd_exec:file *;` and `neverallow phosphor_keygate phosphor_agentd_data_file:file *;` — denying the whole operation set on those two types covers `execute`, `execute_no_trans`, `entrypoint`, `read`, `map`, `write`, `create`, `unlink` and `setattr` together. **`mmap_exec_file_perms` is deliberately *not* named (NEW-7):** it is not defined in this tree (`global_macros:25-35` defines the macro set that is actually available, and that name is not among them), so naming it would make the rule fail to compile for no gain — `:file *` already denies strictly more than the macro would have.
417|- **`phosphor_keygate`'s property access, as a subtraction** (the form used in-tree against `powerctl_prop`): `neverallow phosphor_keygate { system_prop -phosphor_safeboot_prop }:property_service set;` — the subtraction is what makes the rule precise, so the blanket form is deliberately not used. `phosphor_safeboot_prop` is declared `exact bool` (AOSP already ships this shape for `sys.boot_completed`), which is also why no `sys.powerctl`-style name special-casing is needed.
418|- `neverallow phosphor_keygate` binder, network, and any device node other than the key input device.
419|
420|That last group is what makes keygate a one-way switch rather than a privilege: it can withhold the agent, and it has no expressible route to grant anything. sepolicy lives in our build tree's device/platform overlay.
