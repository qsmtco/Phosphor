160|## 4. Acceptance criteria
161|
162|**A1 — Boots to the shell on a normal boot.** After the S3-approved normal boot: the home screen is Phosphor (screenshot evidence), `adb shell dumpsys activity activities | grep -i 'mResumedActivity'` names `com.phosphor.shell/.MainActivity`, and `getprop sys.phosphor.safeboot` → `0`.
163|
164|**A2 — Safe boot lands on the stock launcher.** After the S3-approved safe-boot boot (`persist.phosphor.safeboot=1`): the resumed activity is the **stock** launcher's component, `com.phosphor.shell` appears **finished** (not in the back stack: `dumpsys activity activities` shows no `MainActivity` for our package in the active task), and `pidof com.phosphor.shell` may be empty or absent — the requirement is that it is **not the surface**. Screenshot evidence. Architecture §1.2/§6.5: "launcher + Settings + no agent".
165|
166|**A3 — The three fail-closed hand-off cases.** Each is demonstrated (device or instrumented test with a stubbed property source):
167|- property **absent** ⇒ hand off;
168|- property **unparseable** (e.g. `garbage`) ⇒ hand off;
169|- property **`1`** ⇒ hand off;
170|- property **`0`** ⇒ continue.
171|Pass = all four, with the incidents logged. This is NEW-1's acceptance in the app half.
172|
173|**A4 — Hardening set applied and verifiable.** For each row of §2.3, a code assertion (a `WebView` config dump or a unit test on the setter wrapper) + the CSP test: the rendered document's first `<head>` child is the `Content-Security-Policy` meta with the **exact** directive string of §2.4.
174|
175|**A5 — Subresource allow-list works (`docs/P4-AUDIT.md` H1 re-run, the §4.1 verification).** Load the stub screen **plus** `<script src="https://evil.example/x.js">` and `<img src="https://evil.example/p.png">` into the same hardened WebView. Pass = (i) both blocked, each with a logged `subresource blocked:` note rendered visibly in the note area; (ii) the inline `<script>` in the same document **still executes** (it is what writes `phosphorApi.version()` to the DOM); (iii) `window.phosphorApi` is reachable; (iv) **no network request leaves the device** — proof by `adb shell dumpsys netstats` delta or by absence of any resolution attempt in `logcat`, with the method stated. This is §4.1's Phase 5 acceptance test, and it is S5's central deliverable.
176|
177|**A6 — Exactly one capability permission, one component.**
178|```bash
179|aapt2 dump permissions out/target/product/akita/system/app/PhosphorShell/PhosphorShell.apk   # -> RECORD_AUDIO only
180|aapt2 dump badging …  | grep -E 'launchable|category'                                       # -> HOME/DEFAULT only
181|```
182|Pass = `RECORD_AUDIO` is the only `uses-permission`; the merged manifest has exactly one `<activity>` and zero `<service>/<receiver>/<provider>`; the APK carries **our platform certificate** (§2.1: platform-signed).
183|
184|**A7 — `phosphorApi` is the only bridge and is method-whitelisted.** Code review artifact: exactly one `addJavascriptInterface` call in the module; the proxy class's `@JavascriptInterface` methods are exactly §2.5's four; no reflective dispatch. A test asserts a call to an unlisted method is unreachable (`phosphorApi.secret` is `undefined` in the page).
185|
186|**A8 — No secret in page scope (R-UI-4/R-SEC-2).** The stub page's `document` contains no token, key, or path under `/data`. Grep the built HTML for `token|secret|key=` → only the `phosphorApi` names.
187|
188|**A9 — Offline state is honest.** With nothing to connect to (S5 by construction), the screen states the agent is unavailable rather than showing a fake "ready". This is §2.2's "agent offline, retrying" shape in stub form.
189|
190|**A10 — No binder server, no capability surface.** `dumpsys activity service` shows no service exported by our package; static: no `<service>` (A6). The shell holds no binder *server* (§8 map).

194|## 5. Edge cases
195|
196|| Case | Required behaviour |
197||---|---|
198|| Property read throws / `SystemProperties` unavailable | Catch ⇒ **hand off**. Never propagate, never default to "continue". |
199|| `sys.phosphor.safeboot` = `00`, ` 0`, `0\n` | Parse strictly: trim, then require exactly `"0"` or `"1"`; anything else ⇒ hand off. Do not use `Integer.parseInt` alone (it accepts `+0`/`-0`); accept only the two literal strings. |
200|| Stock launcher absent from the build | Show the minimal fallback text (never crash) and log it as a **build defect**; A2 cannot pass without the stock launcher, so this is a stop-the-line finding. |
201|| Two HOME candidates | First non-Phosphor candidate, order stabilised by sorting component names so behaviour is deterministic across boots. Record the resolved component in the log. |
202|| Explicit component hand-off throws `ActivityNotFoundException` | Fall back to the constant limit: log + minimal text UI; do not re-enter the implicit-HOME loop. |
203|| Shell re-launched from recents in safe boot | `suspendTask`? No: `excludeFromRecents="true"` + re-check in `onResume` (§2.1). |
204|| Page tries `window.location = "https://…"` | `shouldOverrideUrlLoading` refuses and logs; the WebView never leaves `data:`. |
205|| Page tries `fetch()`/`XHR` | `connect-src 'none'` + `blockNetworkLoads`; assert in A5 (iv). |
206|| Model/page emits `<script src>` that Layer 1 (agentd) should have defanged | Not applicable in S5 (no agentd), and this is exactly why A5 injects the hostile tags **directly** into the stub document — S5 must be safe even with Layer 1 absent. |
207|| WebView engine is GrapheneOS-signed, not ours | Accepted (OQ-1 DECIDED, §1.1/§9): the engine's trust anchor is GrapheneOS's. The completion note must **not** claim the shell "owns" the engine — that overstated claim was withdrawn in rev 2 (NOTE-1). |
208|| `RECORD_AUDIO` declared but unused | Recorded (§2.2), not "cleaned up": §2.1 fixes the shell's capability set, and removing the declaration would contradict the architecture. |
209|| Dark-theme/font rendering differences | Out of scope for S5 acceptance; a screenshot is evidence of *which surface*, not of visual quality. |
