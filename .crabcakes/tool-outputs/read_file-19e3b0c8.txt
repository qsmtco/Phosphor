1|# P5-S1 — Build integration: Phosphor repositories and modules in the `akita` build
2|
3|**Phase:** 5 · **Spec ID:** P5-S1 · **Rev:** 1 (draft for PM approval) · **Owner:** Coder (builder) / Debugger (auditor)
4|**Status:** DRAFT — awaiting PM approval. This spec authorizes **no code, no build, no device operation** by itself; the builder executes it after approval.
5|**Depends on:** nothing. Phase 4 architecture `docs/PHASE-4-PLATFORM-ARCHITECTURE.md` rev 4 is **CLOSED**; the Phase 2/3 platform pipeline is proven (`docs/PROJECT-STATUS.md` §6).

7|**Authority:** BUILD-PLAN Phase 5 scope item 1 ("Add the initial Phosphor platform repositories/modules to the build"); architecture §2.1 (process inventory), §8 ("sepolicy lives in our build tree's device/platform overlay"); `docs/PROJECT-STATUS.md` §6 (the verified build recipe), §9 (build traps).

11|## 1. Scope
12|
13|Make the GrapheneOS `akita` build produce **five empty-but-real Phosphor modules** plus the build plumbing that every later spec fills in:
14|
15|| Module (soong name) | Kind | Install location | Behaviour at S1 |
16||---|---|---|---|
17|| `phosphor-agentd` | `cc_binary` | `/system/bin/phosphor-agentd` | stub `main()` → exit 0. Never started (no `.rc` until S4). |
18|| `phosphor-keygate` | `cc_binary` | `/system/bin/phosphor-keygate` | stub `main()` → exit 0. Never started (no `.rc` until S3). |
19|| `phosphor-ctl` | `cc_binary` | `/system/bin/phosphor-ctl` | stub `main()` → prints `phosphor-ctl: not implemented` to stderr, exit 2. (Filled in by S8.) |
20|| `PhosphorShell` | `android_app` | `/system/app/PhosphorShell/PhosphorShell.apk` | valid APK, package `com.phosphor.shell`, **zero declared components**. (Filled in by S5.) |
21|| `PhosphorBroker` | `android_app` | `/system/app/PhosphorBroker/PhosphorBroker.apk` | valid APK, package `com.phosphor.broker`, **zero declared components**, zero permissions. (Filled in by S6.) |
22|
23|Plus: one product fragment, one sepolicy directory wired but empty, one read-only policy artifact staged, and one local-manifest entry.
24|
25|**"Empty" is a hard requirement, not a placeholder word.** An empty module must (a) compile, (b) install to the path above, (c) appear in `product_packages.txt`, and (d) **cause no observable device behaviour change whatsoever** — no process starts, no service registers, no property is written, no file under `/data` is created. S1's acceptance is therefore build-only and static; the first boot check of any Phosphor component belongs to S3/S4 and requires PM approval for that device operation.
26|
27|### Non-goals (explicitly not in S1)
28|
29|- No sepolicy content (S2), no init `.rc` files (S3, S4), no behaviour in any binary or app.
30|- No new `lunch` target. **The build recipe must not change** (see §5 A2).
31|- No device operation of any kind: no flash, no wipe, no reboot, no `adb` write.
32|- No modification of `vendor/google_devices/akita` (generated by adevtool — regenerated, never hand-edited; `docs/PROJECT-STATUS.md` §6).
33|- No `OFFICIAL_BUILD=true` (`docs/PROJECT-STATUS.md` §9 — it points the Updater at GrapheneOS's real server).

51|## 3. Behaviour contract
52|
53|**B1 — One new repository, one mount point.** Phosphor's Phase 5 payload lives in a single new repository mounted at `packages/phosphor/` in the GrapheneOS tree. It is *added by local manifest*, so **no GrapheneOS-owned project is forked and no GrapheneOS file is edited** except the single product-inheritance line in B4.
54|
55|**B2 — Directory layout (canonical for all later specs).**
56|
57|```
58|packages/phosphor/
59|  phosphor.mk                     # product fragment: PRODUCT_PACKAGES, PRODUCT_COPY_FILES, BOARD_*_SEPOLICY_DIR
60|  sepolicy/                       # wired empty in S1; content owned by S2
61|    public/                       # -> BOARD_PLAT_PUBLIC_SEPOLICY_DIR
62|    private/                      # -> BOARD_PLAT_PRIVATE_SEPOLICY_DIR
63|  risk-policy/risk-policy.json    # read-only policy artifact (typed by S2, consumed by S6/S7)
64|  init/                           # empty in S1; phosphor_keygate.rc (S3), phosphor_agentd.rc (S4)
65|  services/PhosphorAgentd/        # cc_binary phosphor-agentd   (S4)
66|  services/PhosphorKeygate/       # cc_binary phosphor-keygate  (S3)
67|  services/PhosphorDiagnostics/   # cc_binary phosphor-ctl      (S8)
68|  services/PhosphorIpc/           # AIDL + wire headers shared by S4/S6/S7
69|  apps/PhosphorShell/             # android_app PhosphorShell   (S5)
70|  apps/PhosphorBroker/            # android_app PhosphorBroker  (S6)
71|```
72|
73|**B3 — Module definitions.** `cc_binary` modules use `stem:` equal to the module name so the installed filename is `phosphor-agentd` etc.; `android_app` modules use `platform_apis: true`, `certificate: "platform"`, `privileged: true`, and a minimal valid `AndroidManifest.xml` (package only, no `<application>` components beyond `android:label`). No module declares `init_rc` in S1 — the `.rc` install is part of S3/S4 so that S1 cannot start anything at boot.
74|
75|**B4 — Product hook, exactly one line in a third-party file.** `packages/phosphor/phosphor.mk` is inherited by appending exactly one line to `vendor/adevtool/config/mk/google_devices/device/akita/device.mk`:
76|
77|```make
78|$(call inherit-product, packages/phosphor/phosphor.mk)
79|```
80|
81|This is the only writable seam: the generated `vendor/google_devices/akita/akita.mk` inherits that file (`docs/PHASE-2-SOURCE-AND-BUILD-FOUNDATION.md` §4), and product inheritance is not otherwise expressible from outside the product's own makefile chain. The consequence is **mandatory**: `PATH="$HOME/android-sdk/node24/bin:$PATH" vendor/adevtool/bin/run generate-all -d akita` must be re-run so `vendor/google_devices/akita` is regenerated from its source config rather than hand-edited. (Trap: adevtool aborts on the nsjail stderr line — re-apply `scripts/host-fix-nsjail-userns.sh` first; it uses the `vendor/adevtool/dl/` cache, so no network is required.)
82|
83|**B5 — `phosphor.mk` content.**
84|
85|```make
86|PRODUCT_PACKAGES += \
87|    phosphor-agentd \
88|    phosphor-keygate \
89|    phosphor-ctl \
90|    PhosphorShell \
91|    PhosphorBroker
92|
93|PRODUCT_COPY_FILES += \
94|    packages/phosphor/risk-policy/risk-policy.json:$(TARGET_COPY_OUT_SYSTEM)/etc/phosphor/risk-policy.json
95|
96|BOARD_PLAT_PUBLIC_SEPOLICY_DIR += packages/phosphor/sepolicy/public
97|BOARD_PLAT_PRIVATE_SEPOLICY_DIR += packages/phosphor/sepolicy/private
98|```
99|
100|Both sepolicy directories ship with a `README` only in S1 (an empty directory in these variables is legal and produces no policy). `[VERIFY AT BUILD: rg -n 'BOARD_PLAT_(PUBLIC|PRIVATE)_SEPOLICY_DIR' build/make/core` — if the variable names differ in this tree, record the actual names in the S1 completion note before writing `phosphor.mk`.]`
101|
102|**B6 — Local manifest.** `.repo/local_manifests/phosphor.xml`:
103|
104|```xml
105|<manifest>
106|  <remote  name="phosphor" fetch="ssh://git@github.com/qsmtco" />
107|  <project name="Phosphor-platform" path="packages/phosphor" remote="phosphor" revision="refs/heads/main" />
108|</manifest>
109|```
110|
111|Development variant (until the remote exists): replace `remote` with `fetch="file:///home/qoder/projects/Phosphor-platform.git"` against a local bare mirror. Afterwards `repo manifest -r > .repo/manifest-pinned.xml` must be re-run so the pin file records our project at a commit hash. The Phase 2 provenance claim (`docs/PHASE-2-SOURCE-AND-BUILD-FOUNDATION.md` §3.4) remains valid for GrapheneOS projects; our project is provenance-recorded separately and this split must be stated in the completion note.
112|
113|**B7 — Stub sources.** `services/*/main.cpp` is exactly:
114|
115|```cpp
116|int main() { return 0; }         // phosphor-ctl prints one line to stderr and returns 2
117|```
118|
119|App stubs contain a single `AndroidManifest.xml` with `<manifest package="com.phosphor.shell">` (resp. `.broker`) and nothing else, and no `src/` beyond an empty package directory.

136|
137|**A1 — Manifest applies.**
138|`repo manifest | grep -c 'path="packages/phosphor"'` → `1`; `repo sync -n` exits 0; `repo manifest -r` output contains the project pinned to a 40-hex commit.
139|
140|**A2 — The recipe is unchanged and the build completes.** Executed verbatim from `docs/PROJECT-STATUS.md` §6:
141|
142|```bash
143|cd ~/projects/grapheneos-2026091900
144|source build/envsetup.sh
145|lunch akita-cur-user
146|m -j24 vendorbootimage vendorkernelbootimage target-files-package
147|```
148|
149|Pass = exit code 0, `ninja: build stopped` absent, `FAILED:` absent, `out/` size delta recorded, and the ninja step count recorded **with its delta against the 168,199 baseline**. No flag, target, variant or `lunch` argument differs from the recipe. `[VERIFY AT BUILD: the "Build sandboxing disabled due to nsjail error." stderr line is expected and is NOT a failure — PROJECT-STATUS §9.]`
150|
151|**A3 — All five modules are installed.**
152|
153|```bash
154|ls -l out/target/product/akita/system/bin/phosphor-agentd \
155|      out/target/product/akita/system/bin/phosphor-keygate \
156|      out/target/product/akita/system/bin/phosphor-ctl
157|out/host/linux-x86/bin/aapt2 dump badging out/target/product/akita/system/app/PhosphorShell/PhosphorShell.apk | head -1
158|out/host/linux-x86/bin/aapt2 dump badging out/target/product/akita/system/app/PhosphorBroker/PhosphorBroker.apk | head -1
159|grep -cE '^(phosphor-|Phosphor)' out/target/product/akita/product_packages.txt
160|```
161|
162|Pass = three binaries present and executable, both APKs report `package: name='com.phosphor.shell'` / `'com.phosphor.broker'` with our platform certificate, and the `product_packages.txt` count is exactly `5`. (`apksigner` needs a JDK on PATH — use `prebuilts/jdk/jdk25/linux-x86/bin/java`, never a bare `find`; PROJECT-STATUS §9.)
163|
164|**A4 — Zero boot-time behaviour.** Static proof, no device: no `init_rc` property in any `Android.bp` under `packages/phosphor` (`rg -n 'init_rc' packages/phosphor` → empty); `rg -n 'sepolicy/.+' packages/phosphor/sepolicy` finds only READMEs; `unzip -l` the two APKs shows a manifest with no `<activity>`, `<service>`, `<receiver>`; `rg -n 'PRODUCT_COPY_FILES' packages/phosphor/phosphor.mk` copies exactly one file and it is the JSON policy artifact.
165|
166|**A5 — Third-party modification surface is exactly one line.** `repo status -j24` (or `git status` per project) shows modifications **only** in `vendor/adevtool` (one line added to `device.mk`) and in `packages/phosphor` (new). Any other modified GrapheneOS project fails this spec. The `repo status` output is attached as evidence.
167|
168|**A6 — Provenance recorded.** Completion note states: (a) our project's commit, (b) the re-pinned `manifest-pinned.xml` line count delta, (c) that GrapheneOS's own signed-tag verification is unaffected, (d) the adevtool regeneration was performed from config, not by hand-editing `vendor/google_devices`.
169|
170|**A7 — No device operation performed.** `git diff` of `docs/` and the absence of any `adb`/`fastboot` invocation in the session log. S1 is a build-only spec; the first boot of Phosphor code is gated behind S3/S4 + PM approval.

174|## 6. Edge cases and failure modes
175|
176|| Case | Required handling |
177||---|---|
178|| `adevtool generate-all` aborts on the nsjail stderr line | Re-apply `scripts/host-fix-nsjail-userns.sh`; do **not** judge the fix with a bare `nsjail` probe (it fails even when correct — PROJECT-STATUS §9). |
179|| `vendor/google_devices/akita` shows the line as hand-edited | Stop; regenerate. A hand-edit is silently lost on the next `generate-all`. |
180|| Module name collision with a GrapheneOS module | Pre-flight `rg -n '"phosphor-|"Phosphor' --glob Android.bp` across the tree before adding; a duplicate soong module name is a hard build error, and GrapheneOS names its apps by module (`PROJECT-STATUS` §9). |
181|| `soong_namespace` in a parent directory hides `packages/phosphor` modules | Verify no `soong_namespace {}` in `packages/` chain; if present, add a matching `soong_namespace` + `import` and record it. |
182|| Disk pressure | `out/` is ~107 GB and the delta must be recorded before the build, not after a failure. |
183|| Build "succeeds" but a module is missing from `product_packages.txt` | This is the exact trap MAJOR-4/§3 warns about in another form: the artifact, not the message, is the evidence. A4/A3 counts are the gate. |
184|| `lunch akita-user` or `akita-ap2a-user` accepted-looking | Rejected by project rule; only `akita-cur-user` continues (`PROJECT-STATUS` §6). |
185|| Fingerprint | Expected to end `:user/test-keys` at this stage — correct, not a defect. |
