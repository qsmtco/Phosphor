291|## 6. Edge cases and failure modes
292|
293|| Case | Required handling |
294||---|---|
295|| `neverallow` in a device dir | Must compile-fail. Confirm C14 first (the dir must be in the `sepolicy_neverallows` source list at `system/sepolicy/Android.bp:943`); if the tree rejects it, the fix is the dir choice, **never** deleting the rule. |
296|| `mmap_exec_file_perms` reintroduced by a helpful editor | Build fails. Cite NEW-7/C11 and restore `:file *`. |
297|| `set_prop(shell, …)` looks like granting the adb user the latch | It is the *point*: the documented writer is the host over adb (`adb shell setprop persist.phosphor.safeboot 1`), and `shell` is that path. The set-only semantics are **not** weakened — C8/C9 mean the rule cannot see a value at all, so "absent→1 only, 0 ignored" remains enforced in keygate's binary (S3 §2.1/2.2), and A10 still forbids any Phosphor domain clearing a safe boot. If someone proposes granting the latch to `phosphor_shell`/`agentd`/`keygate`/`broker` "so it can be cleared on-device", that is a **refused** change: it destroys the one-way property. |
298|| A future rule gives another domain `set` on the latch | §3.4's `neverallow { domain -shell -init } phosphor_safeboot_latch_prop:property_service set` (checked by A5/A7) makes it a **compile error**, which is the intent: "exactly one writer" is enforced, not merely observed. |
299|| `neverallow phosphor_keygate { system_prop -phosphor_safeboot_prop }:property_service set` — subtraction syntax | C10 shows the in-tree shape; if the build rejects the exact string, use the enumerated alternative and record it. Do not fall back to the blanket form (§8 explicitly forbids it). |
300|| `exact bool` on a `persist.*` property | `persist.*` is `string`; use `exact string` for the latch (see §3.1) and keep `exact bool` only for the `sys.*` decision. Mixing them fails at init property-load time, not at build time — a silent-late failure. |
301|| Latch value semantics | `persist.*` must be non-empty; init rejects empty values for `persist.`. `setprop persist.phosphor.safeboot 1` is the only meaningful write. |
302|| Type exists but no context | Property falls back to `default_prop` (C6) and *silently* loses the grant. A4/A5's `rg` on the **compiled** contexts files is the check, not on the source. |
303|| `app_domain()` needs a matching `seapp_contexts` entry | Both halves or the app runs as `untrusted_app` and none of the grants apply — silently. A3's liveness proof covers it. |
304|| Four AIDs collide with an existing OEM AID | `[VERIFY]` at C15; a collision is an SELinux *and* a filesystem-ownership fault. |
305|| `get_prop(appdomain, …)` looks like over-grant | It is intended (§3.3) and mirrors `app.te:40`. Do not narrow it to our two packages without recording why — the safe-boot flag must be readable by anything that must decide whether to be the surface. |
